# 實作練習題

看完《快速上手篇》之後的動手關卡，共 23 題：**基礎 9 題**把課程裡的某一段流程換一份資料練熟，**進階 14 題**是完整的再分析專案，最理想的情況是真的長出一篇可投稿的研究。

這些題目跟課程 R 腳本結尾的「▶ 練習」不一樣。那些是隨堂練習：換個參數重跑、把某張圖換個切法，幾十分鐘就做得完。這裡的題目要你自己找資料、自己下載、自己決定參數、自己寫報告，半天到三個工作天一題。

**所有題目用的都是課程沒教過的資料。** 課堂上示範用的兩份資料（Q2 的 10x GBM 5k、Q3 的 GSE84465）在這裡一份都不會出現——練習如果還是同一批資料，練到的只是重跑一次示範。這 23 題用 23 個不同的公開資料集。

## 怎麼用這個資料夾

- [`基礎/`](基礎) —— 9 張基礎題卡
- [`進階/`](進階) —— 14 張進階題卡
- [`進階/_從練習到投稿指南.md`](進階/_從練習到投稿指南.md) —— 所有進階題共用：再分析的正當切入點、投稿的最低標準、期刊層級怎麼看
- [`資料集總覽.md`](資料集總覽.md) —— 每個資料集的 accession、規模、格式、下載方式

每張題卡的結構固定：背景與研究主題 → 資料集 → 任務（分階段）→ 繳交物 → 自我檢核點 → 提示（卡關再看）→ 參考文獻。進階題多兩節：**真實數據關卡**（讀檔之前的格式解剖、決策日誌）與**發表路徑**（訊號分類、驗證設計、novelty 查證、目標期刊層級）。

## 進階題的階段 D：把課程教的分析全部用上

課程裡 Q3 把下游六條路並排介紹了一遍。每一張進階題卡的**階段 D 會帶你在同一份資料上把它們接成一條線**：

| 步驟 | 做什麼 | 課程腳本 |
|---|---|---|
| D1 | pseudobulk 差異表達，統計單位是病人；每個細胞型別各自校正 | `R/06a_pseudobulk_gsea.R` |
| D2 | 同一組對比再跑 cell-level DE，用三道防線比較兩者結論差多少 | `R/06b_cell_level_de.R` |
| D3 | GSEA／ORA；ORA 的背景用「這次測到的基因」，報 p.adjust | `R/06a_pseudobulk_gsea.R` |
| D4 | CellChat 兩條件分開建物件再比較，並做組成校正 | `R/07_cellchat.R` |
| D5 | 軌跡：起點最好有生物學理由，並排除「只是把細胞週期畫一遍」 | `R/08_trajectory.R` |
| D6 | PROGENy 路徑活性 + SCENIC／decoupleR regulon 活性 | `R/09_activity.R` |
| D7 | 建 signature、MuSiC 反卷積 bulk 隊列、KM 與 Cox 臨床驗證 | `R/10_deconv_survival.R` |

**為什麼每一題都要全部跑過？** 某些步驟對某份資料不見得是最貼切的分析，但走過一遍之後，你才有依據回答「這個分析對這份資料有沒有意義」；而且七條線索都攤開來，也比較容易看出哪一條最有機會長成新的研究論述或假說。

D7 放在最後同樣是刻意的：走完這一步，十幾位病人的單細胞觀察才從描述變成有證據的主張。腫瘤題接對應的 TCGA 專案；肝硬化與肺纖維化沒有 TCGA 對應，要你自己上 GEO 找一個帶臨床變項的 bulk 隊列——那個查找過程本身就是題目的一部分。

**這七步不是每一步在每份資料上都成立。** 進階11 只分選了 T 細胞，完整的通訊網路做不了；進階12、進階13 沒有惡性細胞，inferCNV 只能當陰性對照跑。遇到做不了的步驟，把原因寫下來就好——那段說明跟做得出來的圖一樣有價值，檢核點裡也列了這一條。

## 關於「跟原論文對答案」

進階題大多是重新分析已經發表的資料，所以先把這件事講清楚：**不必跟原論文得到一樣的數字，也幾乎不可能一樣。**

軟體版本、QC 門檻、基因註解、正規化方式、整合方法、分群解析度、DE 方法、基因集資料庫的版本，
還有原論文沒有完整寫出來的處理步驟——任何一項不同，細胞數、群比例、p 值、log2FC、NES 都會跟著變。
所以看到自己的數字跟論文對不起來，第一個念頭不需要是「我做錯了」。

比較值得問的是：**原論文的主要趨勢，換一套流程還站得住嗎？** 舉例來說，原文說某個狀態在某個條件下變多，
你算出來是 31% → 48%，原文是 35% → 55%——這就是很好的重現，不用去追那 4 個百分點。

我們接受三種結果，寫得出理由的都算完成：

| 結果 | 意思 | 報告裡要寫的 |
|---|---|---|
| 一致 | 主要生物學趨勢重現了 | 哪些步驟你做了不同的選擇，趨勢仍然出得來 |
| 部分一致 | 方向對，但效應大小、顯著性或某個亞群不同 | 哪一步造成差異，你怎麼確認的 |
| 不一致 | 沒有差異，甚至方向相反 | 差異的來源，以及原論文的假設有沒有被這份重分析動搖 |

第三種不是失敗。如果你能指出原論文把細胞當成重複、註解規則比較寬鬆，
或某個結論其實對流程選擇很敏感，那比單純重現一次更有價值。

只有一件事要避免：**為了讓數字貼近論文而回頭調參數。** 那是把結論寫在分析前面，
也正好是這門課從第一集就在講的反例。

真正要交出來的不是「跟論文一樣的圖」，而是能說明結果為什麼相同或不同，
以及原論文的結論在你重新分析之後還成不成立。

## 把環境鎖起來（renv）

上面說「用 renv」，這裡講怎麼用。它要解決的問題是：半年後你自己重跑同一份程式碼，
Seurat 可能已經改版、基因集資料庫也更新過，結果對不起來——而你會分不清是分析錯了還是環境變了。
`renv` 把「這次用的每個套件是哪個版本」記進一個 `renv.lock`，別人（或未來的你）照著它就能裝回同一組。

在你的專案資料夾開 RStudio Project，然後：

```r
install.packages("renv")
renv::init()          # 建立專案專屬的套件庫
# …照常做你的分析，跑完之後…
renv::snapshot()      # 掃描程式碼用到哪些套件，寫出 renv.lock
```

換一台機器或交給別人時：

```r
renv::restore()       # 照著 renv.lock 裝回同一組版本
```

幾件實際會踩到的事：

- **`snapshot()` 是靠掃程式碼找套件的**（找 `library()` 與 `::`），所以要在腳本至少載入過一輪之後再跑，
  不然它抓不到你只在某一段用到的套件。
- **從 GitHub 裝的套件要特別確認**。這門課會用到的 DoubletFinder、CellChat、MuSiC、SeuratWrappers
  都在 GitHub 上，而分支是會移動的——今天的 `main` 跟明年的 `main` 不是同一份程式碼。
  打開 `renv.lock` 搜尋這幾個套件，看它們有沒有 `RemoteSha` 那一欄；有 SHA 才算真的鎖住。
  如果沒有（通常是用 `devtools::install_github()` 裝的沒留下記錄），用 `renv::install("user/repo")`
  重裝一次再 `snapshot()`。
- **`renv/library/` 不要上傳**。那是套件本體，好幾 GB。`renv::init()` 會自動幫你加進 `.gitignore`，
  要上傳的只有 `renv.lock` 這個檔。
- **鎖了不等於驗證過**。找一個乾淨的資料夾（或另一台電腦）跑一次 `renv::restore()`，
  確認真的還原得回來再交出去——沒驗證過的 lockfile 只是看起來很專業。
- 光有 lockfile 還不夠：`sessionInfo()` 的輸出、`set.seed(1234)`、以及你用的資料是哪一版
  （GEO accession、下載日期），一起寫進報告才是完整的可重現。

順帶說明：**這門課本身目前還沒有附 `renv.lock`**。課程腳本是在 R 4.4.1 / Seurat 5.3.0 實跑驗證的，
但 `00_setup.R` 是「缺什麼就裝最新版」，所以「同一套環境重跑一致」成立、「明年重新下載也一樣」還不成立。
這是課程自己待補的一項——寫在這裡是因為，要求你做的事，我們自己也還在做。
